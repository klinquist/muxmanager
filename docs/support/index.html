Getting connected

  1. Your computer needs SSH enabled and tmux 3.2 or later. Start a tmux session on the computer first, or create one after connecting.
  2. Tap + in Mux Manager and enter the host, port, and username.
  3. Choose a password or SSH key. Generate an Ed25519 key or import a supported OpenSSH key from the connection editor. Add its public key to your host’s ~/.ssh/authorized_keys using your normal administrative workflow.
  4. Connect and verify the host fingerprint against a trusted source. Choose a session, then open a window.

For an inside host, save the outside/bastion host first, then choose it under Connect through on the inside connection. SSH forwarding must be permitted on the bastion. Both hosts are authenticated and verified separately.

Which display mode should I use?

Smart wraps text locally so you can read without horizontal scrolling, preserving colors and the remote window size. Alignment can change for tables or full-screen interfaces. Original preserves the remote grid and supports scrolling. Fit device changes the remote window size, which can affect other clients viewing it. The app attempts to restore its sizing changes when you leave Fit while connected.

How does autocomplete work?

At a recognizable empty zsh/bash prompt, type a single command line in the native input box and press Tab. The app sends the draft and Tab without Enter, reads the resulting text from the screen, and returns it to the input box. It clears its temporary remote input before you send. It is best effort: custom prompts, shell bindings, completion menus, wide Unicode, and another client typing can make it unreliable. Use Terminal mode when the app cannot read a completion safely. No host installation is required.

Connected, but no windows?

Choose a session if more than one exists. Make sure SSH uses the same user and default tmux socket as your desktop. A custom tmux socket or environment may expose a different server. Open Info → Connection diagnostics, reconnect or refresh, and inspect the tmux path, socket, discovery counts, and selection.

Reading and typing

Scroll up to pause following. Tap Live to put the latest line at the bottom. The keyboard-down button hides the keyboard until you tap the message field again. Terminal mode hides the composer and sends input immediately; Compose keeps a draft until Send. Use the clipboard button or Command-V to paste in Terminal, and Shift-Tab for back-tab. Disconnect is beside the host on the main screen and leaves your remote tmux processes running.

Background connections and sync

iOS can suspend SSH when the app is in the background. tmux continues remotely; reconnect when you return. Sync is automatic. For multiple devices, use the same Apple Account with iCloud and iCloud Keychain enabled. Saved connections work locally when iCloud is unavailable; secrets can arrive separately from connection metadata.

Codex notifications

Open Info → Codex notifications, enable Notify when Codex needs attention, and allow notifications in iOS. Alerts name the host and window; tap one to reopen it. The app checks Codex windows across sessions on connected hosts without installing anything on the host. Detection is best effort and may miss short tasks or custom layouts. Monitoring stops when iOS suspends the app or ends its background runtime. Existing idle windows establish a baseline rather than generating old alerts. If permission was denied, use Open Settings from the notification controls.

What to include in a bug report

Include the app version, iOS/iPadOS version, device, display mode, host OS, tmux version, and steps to reproduce. A redacted screenshot or diagnostic report can help. Diagnostics contain host/user identifiers, paths, and session/window names. Review them before posting.

GitHub Issues are public. Remove private hostnames, IP addresses, usernames, terminal content, and other sensitive details. Never post passwords, private keys, passphrases, or API tokens.
